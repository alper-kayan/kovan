01 · How the system works

From one sentence
to verified code.

Give Kovan a goal. A lead agent turns it into a graph of tasks, a team builds them at the same time, and every task has to pass your project’s own checks before it counts.

  1. 1

    Goal

    Type what you want into the Swarm composer. Kovan reads the goal, suggests a team for it (a lead plus the workers it needs) and shows the budget before anything runs.

  2. 2

    Plan

    The lead writes a task graph. Every task has acceptance criteria, the tasks it depends on and the files it will touch. Tasks that would edit the same files are put in order, and risky ones wait for a person to approve them.

  3. 3

    Build

    Teammates pick up tasks the moment their dependencies are done, in parallel, each in its own Git worktree. Every task has a lifecycle you can watch, a budget it can’t pass and a timeout.

  4. 4

    Check

    Kovan finds the project’s checks (typecheck, tests, lint) and runs them on each finished task. A task that fails goes back to its agent with the failure, for one rework.

  5. 5

    Review

    A separate reviewer reads the diff against the acceptance criteria and gives a verdict. Changed files that no test touches are called out instead of passed over.

  6. 6

    Report

    A completion report says exactly which checks ran and passed, what is still unverified and what it cost. The whole run is in the session journal, ready to replay.

02 · Multiplayer

One session.
Everyone’s agents in it.

Each person prompts their own agent in their own lane, on their own machine. Everyone sees every lane as it streams, and the session keeps one branch and one plan.

  • Approvals anyone can answer. Any editor can approve a command; the first answer wins, and it covers that exact action once.
  • Overlap warnings. If your prompt touches files another agent is editing, Kovan says so before it runs: join, split or carry on.
  • Steer and hand off. Redirect an agent mid-turn, comment on a diff, or hand a task to a teammate with its plan.
  • Roles on the server. Viewer, commenter, editor and owner, checked on every request.

A brain with reasons, not just notes.

Decisions are stored with their rationale, consequences and the files they affect. When a new memory contradicts an old one, both are marked disputed and agents are told, so nobody quietly works from a stale rule.

05 · Control

See what agents cost, change and do.

Tools that make a team of agents something you can measure, not just watch.

Budgets

Limits that hold.

A budget per task and per swarm, a monthly limit for the workspace, and a spend ledger by agent. Estimates come from your own history; calls without a known price are counted, not hidden.

Agent Arena

Same task, side by side.

Run one task with several models in throwaway copies of your repository, checked by your own tests. Compare how often each passes, what it costs and how long it takes.

06 · Modes

Alone, as a team,
or both.

Every workspace has a mode. Change it any time; Kovan adapts what it offers.

Solo

Just you and your agents. No invites and no hand-offs, and suggested swarms stay small (two workers at most) so they don’t outrun your attention.

Team

Shared sessions, live lanes, invites, hand-offs and approvals by any editor. AI teammates join the board alongside people.

Adaptive

Starts solo and opens up the team features the moment someone else joins the workspace.
